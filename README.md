# Service Requests

מערכת לניהול פניות שמגיעות מארגונים: רשימה של 100,000 פניות עם חיפוש, סינון, מיון ודפדוף, נתונים מסכמים לפי סטטוס, ועדכון סטטוס עם הגנה מעדכונים מתחרים והיסטוריית שינויים.

**טכנולוגיות:** .NET 10 · ASP.NET Core · EF Core · SQL Server · Angular 22 · Angular Material

## הרצה

**דרישות:** [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0) · [Node.js 24](https://nodejs.org) · SQL Server LocalDB (מגיע עם Visual Studio, או [להורדה נפרדת](https://learn.microsoft.com/sql/database-engine/configure-windows/sql-server-express-localdb)).

```bash
# 1. ה-API (http://localhost:5150). בהרצה הראשונה: יוצר את בסיס הנתונים ו-100,000 פניות (כ-15 שניות)
dotnet run --project src/ServiceRequests.Api

# 2. הממשק, בחלון נוסף (http://localhost:4200)
cd src/service-requests-ui
npm ci
npm start
```

הממשק מעביר את הקריאות ל-`/api` אל ה-API דרך ה-Proxy של שרת הפיתוח, כך שאין צורך בהגדרת CORS.

- **יצירה מחדש של הנתונים** (מחליפה את כל הקיים): `dotnet run --project src/ServiceRequests.Api -- seed 100000`
- **מחרוזת החיבור** נמצאת ב-`src/ServiceRequests.Api/appsettings.Development.json` (LocalDB, `Integrated Security`). אין בה סיסמה.
- **מסמך ה-API:** `http://localhost:5150/openapi/v1.json` (OpenAPI, בסביבת Development).
- **המשתמש:** אין התחברות בגרסה הזו (ראו "מחוץ להיקף"). הממשק שולח את שם המשתמש בכותרת `X-User-Name` (ברירת מחדל `dana.levi`), והוא נשמר בהיסטוריית השינויים. בלי הכותרת, עדכון סטטוס מחזיר 400.

cd src/service-requests-ui

- **בדיקות היחידה:** כללי מעברי הסטטוס, ולידציה של בקשות, וכלל בחירת התוכנית בחיפוש.
- **בדיקות האינטגרציה:** ה-API האמיתי מול בסיס נתונים שנוצר לכל מחלקת בדיקות ונמחק בסופה. כוללות עשרה עדכונים מתחרים לאותה פנייה (אחד מקבל 200, תשעה 409, ונשמרת שורת היסטוריה אחת), Bulk עם הצלחה חלקית, ומרוץ בין חישוב הסיכום לעדכון.
- **בדיקות הממשק:** מצב ה-URL, ביטול בקשות קודמות, Debounce, ניסיונות חוזרים, דיאלוג ההתנגשות ונגישות המקלדת.
- **בדיקות המנגנונים הקריטיים נבדקו גם הן:** הוסר זמנית המנגנון (בדיקת הגרסה, מספר הדור ב-Cache, ביטול הבקשות) ונבדק שהבדיקה נכשלת.

ה-CI ב-GitHub Actions מריץ את שתי החבילות בכל PR, השרת מול SQL Server 2022 בקונטיינר. Merge אפשרי רק כששתיהן עוברות.

## ארכיטקטורה

```
Api            Controllers, טיפול גלובלי בשגיאות (ProblemDetails), המשתמש הנוכחי
 └ Application תרחישי השימוש: חיפוש, סיכום, עדכון סטטוס, Bulk
    └ Infrastructure  EF Core, DbContext, Migrations, Seed
       └ Domain       הפנייה, מעברי הסטטוס והכללים העסקיים, בלי תלות בספרייה
```

**מעברי סטטוס** (מוגדרים במקום אחד, `StatusTransitions`): חדשה → בטיפול · בטיפול → ממתינה או הושלמה · ממתינה → בטיפול · הושלמה היא סטטוס סופי. ה-API מחזיר לכל פנייה את המעברים המותרים לה, והממשק מציג כפתורים רק להם.

**הממשק:** Angular עם Signals ו-OnPush. ה-URL הוא מקור האמת של הסינון, המיון והעמוד, כך שרענון, Back וקישור משותף מציגים את אותה תצוגה. בקשה חדשה מבטלת את הקודמת (`switchMap`), והחיפוש ממתין 300ms אחרי ההקלדה.

## ההחלטות המרכזיות

### 1. Optimistic Concurrency עם `rowVersion` בגוף הבקשה
כל פנייה נושאת `rowversion` של SQL Server. הלקוח שולח את הגרסה שהוא ראה, והעדכון נכשל אם מישהו שינה את הפנייה בינתיים. התשובה היא 409 עם המצב העדכני של הפנייה, כך שהממשק מציג אותו מיד, בלי בקשה נוספת. שינוי הסטטוס ושורת ההיסטוריה נשמרים באותה טרנזקציה. [ADR 0004](docs/adr/0004-rowversion-in-request-body.md)

### 2. Cache לסיכום עם מספר דור (Generation Key)
הסיכום בלי סינון, החישוב הכי יקר והמסך שכל משתמש פותח, נשמר ב-HybridCache תחת מפתח שכולל מספר דור. כל עדכון מעלה את המספר. חישוב ישן שמסתיים אחרי העדכון נכתב תחת הדור הקודם, שאף אחד כבר לא קורא, ולכן לא חוזר נתון ישן. HybridCache מריץ את החישוב פעם אחת גם כשהרבה בקשות מגיעות יחד. [ADR 0006](docs/adr/0006-hybridcache-generation-key.md)

| מגבלה | השפעה שנמדדה | תיקון מוצע | הערכה |

| ה-Cache בזיכרון של מופע אחד | בכמה מופעים, כל אחד מחזיק דור משלו | Redis כשכבה שנייה של HybridCache, ומונה הדור ב-Redis (`INCR`) | 2 שעות |

## מחוץ להיקף

- **התחברות והרשאות.** לא סעיף של המבדק, וההחלטה התקבלה בנקודת ההחלטה שתוכננה מראש ([תוכנית העבודה](docs/WORK_PLAN.md)). השרת מוכן: המשתמש מגיע מ-`ICurrentUser`, כך שמעבר ל-JWT מחליף מחלקה אחת. [ADR 0007](docs/adr/0007-no-authentication-in-this-version.md)
- **בחירת כמה פניות בממשק לעדכון מרוכז.** ה-API תומך בזה (`POST /api/requests/bulk-status`, עד 100 פניות, הצלחה חלקית). [ADR 0005](docs/adr/0005-bulk-partial-success.md)
- **פריסה בפועל לענן**, Full-Text Search, Keyset Pagination, Redis בפועל, API Versioning.
