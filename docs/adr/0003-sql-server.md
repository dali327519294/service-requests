# 0003 – SQL Server

**סטטוס:** התקבלה · 02/11/2026

## הקשר
המערכת מחזיקה 100,000 פניות, עם סינון, מיון ודפדוף, עדכונים מקבילים ויומן ביקורת.
בסיס הנתונים צריך לזהות התנגשויות בעדכון, לאכוף ערכים חוקיים ולאפשר מדידת ביצועים.

## החלטה
SQL Server, דרך EF Core 10 ו-Migrations.
- **פיתוח:** LocalDB, בלי שרת ובלי סיסמה (אימות Windows).
- **CI:** ‏SQL Server 2022 ב-Container.
- **בדיקות אינטגרציה:** כל מחלקת בדיקות יוצרת בסיס נתונים משלה מה-Migrations האמיתיות, ומוחקת אותו בסוף.

## חלופות שנשקלו
- **PostgreSQL:** חינמי וחזק, אבל אין לו מקבילה מובנית ל-`rowversion`, והוא פחות נפוץ בסביבות Microsoft ארגוניות.
- **ספק InMemory של EF Core לבדיקות:** מהיר, אבל לא אוכף `rowversion`, אילוצי CHECK או מפתחות זרים. בדיקות מולו היו עוברות גם כשהסכמה שגויה.
- **SQLite לבדיקות:** מנוע אחר מזה שבפרודקשן, בלי `rowversion` ובלי `INCLUDE` באינדקסים.

## השלכות
- `rowversion` מתעדכן אוטומטית בכל שינוי, ועליו נשען זיהוי ההתנגשויות (Optimistic Concurrency).
- אילוצי CHECK נבנים מתוך ה-Enums, כך שבסיס הנתונים והקוד מסכימים תמיד על הערכים החוקיים.
- SQL Server לא שומר אזור זמן. כל התאריכים נשמרים ב-UTC ומסומנים כ-UTC בקריאה.
- הגרסאות שונות: ‏LocalDB בפיתוח הוא SQL Server 2025, וה-CI רץ על 2022. לכן הקוד משתמש רק ביכולות שקיימות ב-2022.
- בדיקות האינטגרציה איטיות יותר מבדיקות יחידה (כשנייה למחלקה), אבל בודקות את מה שירוץ בפועל.
